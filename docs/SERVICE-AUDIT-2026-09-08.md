# 24Houring 서비스 종합 분석 — 2026-09-08

## 판단과 범위

가장 먼저 개선할 것은 **사용자가 첫 시간표를 완성하고 다음 날 다시 쓰는 흐름**이다. 원형 시간표라는 시각적 차별점, 로그인 없는 편집, 템플릿·내보내기·공유·실제 기록은 좋은 자산이다. 이들을 한 가지 가치로 묶고, 신뢰·접근성·초기 로딩을 정비한 다음 유입을 확대하는 순서를 권한다.

제안하는 중심 메시지: **“하루를 원으로 계획하고, 실제 쓴 시간과 비교하세요.”** 외부 유입용 보조 문구: “가입 없이 시작하는 24시간 계획표. 공부·일·휴식의 균형을 한눈에.” 시장 검증 전 가설이며, 사용자 조사로 선택해야 한다.

- 기준 코드: `8cf66df`, 배포 서비스 `https://24houring.com/ko/`.
- Chromium, 한국어, 데스크톱 1440×1000 및 모바일 크기 390×844, 신규/재방문 상태 4개를 확인했다. 재방문은 실제 고객 이력이 아니라 onboarding 플래그만 설정한 새 컨텍스트다.
- 스크린샷은 최초 렌더 직후와 6초 대기 후 촬영. 광고·분석 도메인은 차단해 감사 트래픽 오염을 줄였다. 따라서 광고 포함 정상 세션의 전체 로딩 결과와 다르다.
- axe-core 자동 검사와 코드 검토를 수행했다. 구매, 로그인, 실제 기기 스크린리더, 사용자 인터뷰는 수행하지 않았다.
- GA4, Search Console, 운영 매출·가입자·리텐션 집계는 열람하지 않았다. 아래의 이탈·전환·수익 효과는 검증할 가설이며 현재 실적이 아니다.
- Chrome DevTools MCP가 없어 해당 전용 성능 감사는 수행하지 않았다. 아래 수치는 일반 Chromium 관찰 및 기존 빌드 크기이며 Lighthouse 점수나 실사용자 Core Web Vitals가 아니다.
- 코드/운영 데이터는 수정하지 않았다. 분석 산출물만 추가했다.

## 유지할 강점

1. **원형 시간표의 인지적 차별성:** 하루에서 각 활동이 차지하는 비중이 바로 보이고, 결과물이 공유 가능한 이미지가 된다.
2. **낮은 시작 장벽:** 기본 계획 작성에 설치·로그인이 필요하지 않다. 유입용 템플릿에서 제품으로 바로 연결할 수 있다.
3. **이미 갖춘 반복 사용 재료:** 계획, 실제 시간 기록, 일기, 주간 회고, 알림이 있다. 새 기능보다 연결 순서 개선의 여지가 크다.
4. **콘텐츠와 확산 자산:** 상황별 템플릿, 가이드, 다국어, PNG/PDF, 짧은 공유 링크, UTM 문서가 있다.
5. **품질 기반:** 앞선 수정에서 테스트 613개, 선택 E2E 8개 묶음, 빌드·린트가 통과했다. 다만 이는 사업 성과나 접근성 적합성을 보증하지 않는다.

## 디자인·UI 제안

현재의 파스텔 원형, 밝은 배경, 여백은 유지할 가치가 있다. 개선의 중심은 새 색상이나 효과보다 **텍스트 크기, 조작 의미, 주요 행동의 우선순위**다.

- 데스크톱: 원형과 함께 오른쪽에 오늘 일정 목록 또는 선택한 일정 편집을 배치하는 안을 시험한다. 넓은 빈 공간을 모두 위젯으로 채우지 않는다.
- 모바일: `오늘 / 기록 / 회고 / 더보기`처럼 짧은 라벨을 제공하고, `+ 일정 추가`를 일관된 위치에 둔다. 바텀 내비게이션은 후보이며 실제 손가락·키보드 사용 테스트로 결정한다.
- 원형은 비중 파악에 활용하고 상세 시간·제목은 목록에서 읽을 수 있게 한다. 짧은 슬라이스의 작은 글자를 확대하는 것만으로 해결하려 하지 않는다.
- 캘린더/날짜 추가의 단독 `+`는 일정 추가와 혼동될 수 있어 “날짜 추가” 텍스트 또는 명확한 맥락을 부여한다.
- 기본 화면은 계획에 집중하고 뉴스·날씨·다마고치·장식은 사용자가 선택해 켜도록 시험한다. 기능 삭제를 전제하지 않는다.
- 테마·폰트·배경을 개별 선택시키기 전에 “차분한 / 산뜻한 / 집중” 같은 완성형 프리셋 3개를 제시하고 상세 조정은 접는다.
- 색, 간격, 글자, 버튼, 팝업의 공통 토큰을 정리해 신규 기능마다 시각 언어가 달라지지 않도록 한다.

### 접근성 결과의 해석

자동 검사에서 aria-required-attr, button-name, color-contrast, nested-interactive 네 유형이 상태별로 보고됐다. 4개 화면 모두 수평 넘침과 pageerror는 관찰되지 않았다. 이는 모든 화면의 접근성/안정성 보장이 아니다.

일반 보조 문구에는 약 3.29:1~3.6:1 대비가 보고됐다. 작은 일반 텍스트의 목표를 4.5:1로 관리하되, 함께 보고된 브랜드 로고는 로고 예외 가능성이 있으므로 자동 검사 결과 그대로 결함으로 세지 않는다. [W3C 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

주요 터치 목표는 44×44px 이상을 설계 목표로 권한다. 이는 모든 작은 버튼이 WCAG 위반이라는 뜻이 아니다. WCAG 2.2 AA의 최소 목표는 24×24px이며 간격·대체 조작 등의 예외가 있다. 상단 32×44px 버튼은 텍스트 없는 의미 전달과 편의성 개선 대상이다. 다마고치 `+`는 22×22px로 측정됐지만 간격 예외를 판정하지 않았다. [W3C 목표 크기 기준](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

## 첫 사용과 반복 사용 재설계

첫 방문의 목표를 “모든 기능 소개”가 아닌 “내 하루를 한 번 만들어 봄”으로 둔다.

1. “예시로 시작 / 직접 만들기” 선택. 템플릿 유입은 해당 예시로 바로 진입한다.
2. 첫 일정 이름·시간 수정 한 번을 안내한다. “퇴근 후 30분 걷기”처럼 구체적 예시를 쓴다.
3. 바뀐 시간 비중과 **실제 기기 저장 완료**를 보여 준다.
4. 다음 행동은 저장한 시간표 공유 또는 오늘 실행 중 한 가지를 맥락에 맞게 제안한다.
5. 꾸미기·알림·앱 설치는 사용자가 가치를 본 뒤 필요할 때 선택한다.

재사용 흐름은 “오늘 계획 → 실제 기록 → 하루 마감 → 다음 날 복제/조정”으로 묶는다. 현재 무료 실제 기록 리포트와 Pro 일기 기반 계획 분석은 데이터 원천이 다르므로 화면 제목·설명에 이를 밝힌다. 알림 허용률만을 제품 가치로 판단하지 않는다.

소규모 사용성 조사 제안: 우선 5명 안팎에게 설명 없이 일정 수정, 실제 기록 시작, 다음 날 계획, 공유, 무료/Pro 구분을 수행하게 한다. 이는 문제 발견용이며 시장 대표성·통계적 우월성 증거로 쓰지 않는다.

## 포지셔닝·마케팅

[Structured](https://structured.app/)는 할 일과 일정을 시각적 타임라인으로 묶는 메시지가 명확하고, [Tiimo](https://www.tiimoapp.com/)는 다양한 neurotype을 위한 시각적 계획과 실행 지원을 전면에 둔다. 경쟁사의 기능 수나 인기도를 추정하기보다 **누구의 어떤 문제를 해결하는지 바로 전달하는 방식**을 참고한다. ADHD 효과 등 임상적 효능은 검증 없이 주장하지 않는다.

첫 실험 타깃 후보는 다음 두 상황이다. 시장 크기·구매력이 검증됐다는 의미는 아니다.

| 후보 | 사용 상황/카피 가설 | 보여줄 결과물 | 유입 실험 |
|---|---|---|---|
| 학습 계획 사용자 | “공부와 쉬는 시간이 함께 보이는 하루 계획표” | 시험기간/방학의 원형 시간표와 인쇄 예시 | 기존 템플릿 SEO, 관련 커뮤니티의 실제 사용 사례 |
| 일하는 개인 | “퇴근 후 내 시간이 어디로 가는지 한눈에” | 업무·수면·휴식 비중과 다음 날 계획 | 짧은 전후 비교 영상, 주간 회고 콘텐츠 |

유입용 페이지는 한 가지 상황, 완성된 원형 예시, 가입 없이 시작하는 단일 CTA를 제공한다. 편집기 기존 사용자를 긴 마케팅 페이지로 강제 이동시키지 않는다. 핵심 랜딩 2개부터 메시지를 시험하고 페이지 수를 먼저 늘리지 않는다.

이미지 자체가 확산 자산이므로 “원형 카드 → 읽기 전용 공유 화면 → 이 시간표로 내 계획 만들기”를 측정한다. 공유 완료 이벤트는 이미지 다운로드도 포함할 수 있어 실제 외부 확산과 분리해야 한다. 공개 공유할 일정·메모 범위를 미리 보여 주고 사용자 선택을 유지한다.

Pinterest/Instagram/한국어 커뮤니티는 후보 채널이다. 초기에는 적은 콘텐츠로 유효 사용자 유입을 비교하고, 유료 광고 증액은 활성화·재사용 기준을 만든 뒤 판단한다. 특정 채널 ROI, CAC 목표 금액은 현재 데이터 없이 정하지 않는다.

SEO는 콘텐츠가 없는 상태가 아니다. 템플릿·가이드 유입이 실제 편집으로 이어지는지를 먼저 연결한다. 일부 템플릿의 ko/en hreflang은 같은 URL을 가리키고 브라우저 언어로 표시를 전환한다. 핵심 페이지부터 언어별 URL·title·본문을 명확히 분리하는 안을 검토하되, 검색 페널티가 발생했다고 단정하지 않는다. 가격 하드코딩(`index.html:129`)과 동적 Polar 가격이 장기적으로 어긋나지 않도록 갱신 경로도 통일한다.

## 수익화·계측·운영

Pro는 “기능 더 많이”보다 “기기를 바꿔도 이어 쓰기 / 오래 기록한 자료 보관 / 지난 시간 비교”라는 결과를 설명한다. 무료 범위를 축소하기 전에 현재 한도 도달과 Pro 진입 맥락을 측정한다. 두 번째 기기 사용·저장 한도·회고 열람 등 해당 가치가 필요한 순간의 안내를 시험한다. 가격 변경은 유지율·체험 종료·환불 자료를 본 뒤 별도 결정한다.

권장 이벤트 정의:

| 단계 | 이벤트 후보 | 주의점 |
|---|---|---|
| 유입 | content_view, template_cta_click | 허용된 분석 설정 안에서 source/template ID를 전달 |
| 첫 가치 | meaningful_schedule_edit, local_save_success/failure | 프리셋 불러오기·꾸미기·자동 변경과 실제 사용자의 시간/제목 편집 구분 |
| 재사용 | record_start, diary_save_success, weekly_review_open | D1/D7의 단순 방문과 실제 계획/기록 행동을 별도 집계 |
| 확산 | share_created, share_view, shared_template_used | 다운로드를 공유 수신으로 간주하지 않기 |
| 전환 | upgrade_open(source), price_loaded, checkout_start, trial_started, subscription_paid | 서버 결제 확정과 분석 집계 대조, event ID로 중복 방지 |

첫 활성화 정의 후보: “사용자가 직접 제목 또는 시간을 수정하고 기기 저장에 성공”. 이 정의와 D7 실제 재사용의 관계를 먼저 살핀다. 북극성 지표 후보는 “주간 2일 이상 자기 계획을 편집하거나 실제 시간을 기록한 사용자 수”이며, 이 역시 운영 데이터로 조정한다.

데이터 최소화: 현재 `schedule_import`가 일정 이름을 파라미터로 보내는 경로(`src/App.tsx:864`)가 있으므로 고정 template ID/source로 대체를 검토한다. 일정 제목·일기·메모 원문은 분석 이벤트로 보내지 않는다. 법적 준수 여부를 이번 감사로 판정하지 않는다.

운영 지표는 페이지 uptime 외에 저장 성공, 동기화 실패·충돌, 가격 조회 실패, webhook 처리·구독 집계 일치, 클라이언트 오류를 포함한다. 피드백 창구는 문제 발생 화면·오류 유형을 받을 수 있게 하되 일기 내용 수집은 피한다. 기존 health endpoint 정상 응답만으로 모든 결제/동기화 경로 성공을 판단하지 않는다.

## 실행 순서

기간은 1~2인 팀의 순서 제안이며 확정 견적이 아니다. 유입이 적으면 A/B 검정 대신 과제 관찰과 순차 출시를 활용한다.

| 시기 | 작업 | 완료 판단 |
|---|---|---|
| 1주차 | 저장 상태 연동, 무료/Pro 문구 통일, 접근성 필수 속성·이름, 퍼널 정의 | 실패 시 거짓 Saved 없음, 언어별 요금 설명 일치, 핵심 조작 수동/자동 확인 |
| 2주차 | 초기 폰트·내보내기 의존성 분리, 첫 일정 중심 온보딩 실험 | 동일 조건 초기 전송량 비교, 내보내기 기능 유지, 첫 일정 과제 성공 관찰 |
| 3~4주차 | 모바일 라벨·일정 목록·계획/기록 탐색, 타깃 랜딩 2개 | 핵심 과제 시간/오류 비교, 콘텐츠→활성화 계측 연결 |
| 5~6주차 | 다음 날 재사용·주간 회고 연결, 공유 수신 경로·맥락별 Pro 안내 | cohort별 D7 행동 재사용과 체험→유료 유지 추적 |

바로 시작할 묶음은 **저장·요금 신뢰 정비 + 접근성 기본 + 첫 계획 중심 온보딩 + 초기 번들 축소**다. 대규모 디자인 전면 교체, 새 위젯 추가, 콘텐츠 대량 증설, 광고 예산 확대는 그 이후 판단한다.

## 증거와 한계

로컬 증거: `.omc/research/service-audit/observations.json` 및 `desktop-first-*`, `desktop-return-*`, `mobile-first-*`, `mobile-return-*` PNG. 스크린샷·결과는 분석용 보관물이며 `.omc`는 Git에서 제외된다.

고객 관점의 문제 가설과 코드상의 기능 확인을 구분했다. 현재 전환율·매출·채널 성과, 실제 휴대폰 터치/보조기술, 느린 네트워크의 반복 측정, 로그인/결제 전체 시나리오는 후속 검증 사항이다. UI 변경은 아직 구현하지 않았다.
