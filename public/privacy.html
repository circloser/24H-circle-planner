1. 기본 플래너의 기기 내 저장 / Default local storage

기본 플래너 편집에는 계정이 필요하지 않습니다. 시간표·메모·일기·환경설정의 기본 저장 위치는 이용자 브라우저(기기)의 로컬 저장소(localStorage)입니다. 로그인, 동기화 또는 서버 공유 링크를 이용하면 아래에 설명된 정보가 서버로 전송됩니다. 로컬 데이터는 브라우저의 사이트 데이터 삭제나 앱의 ‘전체 초기화’로 지울 수 있지만, 이는 이미 서버에 저장된 계정·동기화·공유 데이터 삭제를 뜻하지 않습니다.

Basic planner editing requires no account. Schedules, memos, diary and settings are saved in your browser’s local storage (localStorage) by default. Sign-in, sync and server-hosted share links transmit the information described below to the server. Clearing site data in your browser or using “Reset all” removes local data; it does not delete account, sync or shared data already stored on the server.

2. 로그인 및 클라우드 동기화 (선택)

이용자가 선택적으로 Google 계정으로 로그인하면 세션 유지와 이용 권한 확인에 필요한 계정 정보가 서버(Cloudflare)에 저장됩니다. 여러 기기에서 데이터를 이어 쓰는 클라우드 동기화는 Pro 이용 권한이 있는 계정에서 사용하며, 동기화를 사용하는 경우 일정 데이터도 서버에 저장됩니다. 정보의 범위는 다음과 같습니다.

  • 계정 식별자: Google이 제공하는 고유 식별자(sub)와 이메일 주소. 로그인 세션 유지 및 구독 확인 목적으로만 사용합니다.
  • 동기화 데이터: 시간표·일기·노트·메모·목표·기록·환경설정. 전송 구간은 HTTPS로 암호화됩니다.

기본(표준) 동기화에서는 위 데이터가 서버에 평문(암호화되지 않은 형태)으로 저장됩니다. 즉 서비스 제공·장애 대응·법령상 의무 이행에 필요한 경우, 기술적으로 운영자가 이를 열람할 수 있습니다. 운영자는 이러한 목적 외에 개별 이용자의 데이터에 접근하지 않는 것을 원칙으로 합니다.

일기 잠금(종단간 암호화, E2EE)을 켜면 동기화할 일정 데이터가 이용자 기기에서 설정한 암호로 암호화된 뒤 서버에 전송됩니다. 서버에 저장된 이 동기화 암호문을 읽으려면 해당 암호화 키가 필요하며, 운영자는 이용자의 암호를 받아 복구하는 기능을 제공하지 않습니다. 암호를 잊으면 암호화된 클라우드 기록을 복원하지 못할 수 있습니다. 이 보호는 동기화 데이터에 관한 설명이며 계정 식별 정보, 공개 공유 링크와 이미지에는 적용되지 않습니다.

로그인하지 않으면 클라우드 동기화는 동작하지 않습니다. 다만 아래의 서버 공유 링크는 로그인 없이도 사용할 수 있습니다. 로그아웃 및 계정·데이터 삭제 요청은 singlena@gmail.com으로 접수할 수 있습니다.

If you optionally sign in with Google, we store your Google account identifier (sub) and email on the server (Cloudflare) to keep your session and check subscription. Cross-device cloud sync is available to accounts with Pro entitlement. When sync is used, we also store sync data (schedules, diary, notes, memos, goals, records, settings), encrypted in transit via HTTPS. In standard sync this data is stored on the server as plaintext, so the operator can technically access it where necessary to provide the service, address incidents, or meet legal obligations; the operator does not access individual data otherwise. If you enable diary lock (end-to-end encryption), schedule data to be synced is encrypted on your device using your passphrase before upload. Reading this stored sync ciphertext requires the corresponding encryption key; the operator does not provide recovery by receiving your passphrase. Losing it may prevent recovery of encrypted cloud records. This protection concerns sync data, not account identifiers, public share links or images. Without signing in, no cloud sync occurs, but server-hosted sharing below can be used without an account. Account/data deletion requests: singlena@gmail.com.

구글 캘린더 불러오기 (선택) / Optional Google Calendar import

Pro 이용자가 구글 캘린더의 비공개 iCal 주소를 입력하면 해당 캘린더의 일정을 달력에 함께 볼 수 있습니다. 이 기능은 일기 잠금(종단간 암호화)을 설정한 경우에만 사용할 수 있습니다. 입력한 주소는 다른 기기에서도 같은 캘린더를 보기 위해 동기화 데이터에 포함되며, 잠금이 설정되어 있으므로 기기에서 암호화된 뒤 서버에 저장됩니다. 달력을 여는 시점에 기기가 그 주소를 서비스 서버(Cloudflare Worker)로 보내고(요청 본문으로 전송되며 주소창이나 요청 URL에는 포함되지 않습니다), 서버는 구글에서 일정 데이터를 받아 기기로 전달합니다. 서버는 주소와 일정 내용을 저장하지 않으며, 요청을 줄이기 위해 응답이 최대 10분 동안 임시 캐시될 수 있습니다. 내려받은 일정 내용은 각 기기에만 보관되고 서버로 올라가지 않습니다. 불러온 일정은 읽기 전용으로만 표시되며, 서비스는 구글 캘린더에 어떤 변경도 기록하지 않습니다. 연결을 해제하면 주소와 내려받은 일정이 삭제됩니다. 이 주소는 아는 사람이면 누구나 해당 캘린더를 열람할 수 있으므로 비밀번호처럼 취급하시기 바랍니다.

A Pro user can enter the private iCal address of a Google calendar to see its events alongside their own. The feature is available only with the diary lock (end-to-end encryption) enabled. The address is included in sync data so the same calendar appears on the user’s other devices, and because the lock is on it is encrypted on the device before it is stored on the server. When the calendar is opened, the device sends the address to our server (a Cloudflare Worker) in the request body — never in the address bar or request URL — and the server fetches the calendar from Google and passes it back. The server stores neither the address nor the calendar content; a response may be cached temporarily for up to 10 minutes to limit requests. Downloaded calendar content is kept on each device and is never uploaded. Imported events are shown read-only: the service never writes anything back to Google Calendar. Disconnecting deletes the address and the downloaded events. Anyone holding this address can read that calendar, so treat it like a password.

서버 공유 링크 (선택) / Optional server-hosted sharing

서버 공유 링크를 만들면 공유 대상으로 선택한 시간표 데이터, 시간표 이름 및 생성된 경우 미리보기 이미지가 서버에 저장됩니다. 이 기능에는 로그인이 필요하지 않습니다. 남용 방지를 위해 요청 IP에서 만든 해시 값과 생성 시각도 저장합니다. 링크를 아는 사람은 공유 내용을 열람하거나 다시 전달할 수 있습니다. 일기 잠금은 이러한 공개 공유 데이터를 암호화하지 않으므로 공유 전에 개인 일정과 이름을 확인하세요.

Creating a server-hosted share link stores the selected schedule data, schedule name and a preview image when generated. No sign-in is required. A hash derived from the request IP and the creation time are also stored to limit abuse. Anyone with the link can view or forward the shared content. Diary lock does not encrypt this public share data, so check private schedule details and names before sharing.

라이프(인생 타임라인) / Life timeline

라이프 기능을 쓰면 본인의 생년월일(필수)·이름(선택)·기대 수명 설정, 인생의 사건과 계획(날짜, 제목, 설명, 분류, 계획 여부), 부모님 정보(어머니·아버지의 이름, 생년월일·메모는 선택), 남기고 싶은 말이 기록됩니다. 기본 저장 위치는 다른 기록과 같이 이용자 브라우저의 로컬 저장소이며, Pro 클라우드 동기화를 켜면 사진을 제외한 라이프 기록이 다른 동기화 데이터와 함께 서버에 저장됩니다(일기 잠금을 켠 경우 암호화된 상태로 저장).

사진은 Pro에서만 넣을 수 있고, 사진을 추가한 기기의 브라우저(IndexedDB)에만 저장됩니다. 동기화를 켜도 사진은 서버로 전송되지 않습니다. 이미지(PNG) 내보내기와 JSON 백업 파일은 이용자의 기기에서 만들어져 이용자가 고른 위치에 저장되며, 서버로 전송되지 않습니다. 이후 그 파일을 누구와 공유할지는 이용자가 정합니다.

부모님의 이름·생년월일은 이용자 본인이 아닌 제3자의 개인정보입니다. 동의를 받아 기록해 주시고, 동기화를 켜면 해당 정보가 서버에도 저장된다는 점을 알려 주시기 바랍니다. 운영자는 이 정보를 기록의 보관·동기화 외의 목적(마케팅·분석 등)으로 이용하지 않습니다. 기기에 저장된 기록은 이용자가 지우거나 브라우저 데이터를 삭제할 때까지 남아 있으며, 서버에 동기화된 기록은 이용자가 기록을 지우거나 계정 삭제를 요청하면 삭제됩니다.

자서전(1회 결제): 라이프 화면에서 이용자가 직접 요청하고 결제한 경우에만, 해당 시점의 사건 날짜·제목·설명·분류와 이름·생년월일(입력한 경우), 남기고 싶은 말, 이용자가 적은 요청 문구가 글을 쓰기 위해 Anthropic PBC의 Claude API(미국)로 전송됩니다. 사진과 부모님 정보는 전송되지 않습니다. 운영자는 전송한 내용과 완성된 글을 서버에 저장하지 않으며(결제·사용 횟수만 기록), 완성된 글은 이용자 기기에 저장되고 Pro 동기화를 켠 경우 다른 라이프 기록과 함께 동기화됩니다. Anthropic은 API로 받은 내용을 모델 학습에 사용하지 않으며, 남용 방지 목적의 보관 정책은 Anthropic의 개인정보처리방침을 따릅니다. 이 기능을 쓰지 않으면 라이프 기록은 서버로 전송되지 않습니다.

The Life timeline records your birthday (required), name (optional) and expected life span, the moments and plans you write (date, title, description, category, whether it is a plan), your parents’ details (mother’s and father’s names; birthday and note optional) and the words you would like to leave behind. Like everything else, these are saved in your browser by default; with Pro cloud sync on, the life record — photos excepted — is stored on the server together with your other sync data (encrypted when the diary lock is on). Photos can be added with Pro only, stay in the browser (IndexedDB) of the device that added them, and are never uploaded, even with sync on. The PNG export and JSON backup are made on your device and saved where you choose; whom you share them with is up to you. Your parents’ names and birthdays are personal information about other people: please record them with consent, and let them know that sync also stores them on our server. We use these details only to keep and sync your record — never for marketing or analysis. Records on your device remain until you delete them or clear browser data; synced records are deleted when you delete them or ask us to delete your account.

Memoir (a single purchase): only when you ask for it and pay for it, the dates, titles, descriptions and categories of your moments, your name and birthday if you gave them, the words you would like to leave behind and whatever you asked of the writer are sent to Anthropic PBC’s Claude API (United States) so that the text can be written. Photographs and your parents’ details are not sent. We do not store what was sent or what came back (only the purchase and how many memoirs were written); the finished text is saved on your device, and travels with the rest of your life record if Pro sync is on. Anthropic does not train models on API content; its own privacy policy governs how long it keeps anything for abuse monitoring. If you never use this feature, your life record is never sent anywhere.

The Relation map records the names you write down, their group (family, friends, work, other), how you know them, how close they are, their birthday, when you last had contact, a note, and any lines you draw between people. Like everything else it is saved in your browser by default; with Pro sync on it is stored on our server too — photos excepted — and encrypted when the diary lock is on. Most of this is personal information about other people. Nobody is ever notified that they are on your map, we never show it to another user, and we use it only to keep and sync your record — never for marketing, analysis or matching people to each other. Please only add photographs the person has agreed to. Photos are Pro-only, stay in the browser of the device that added them, and are never uploaded. The PNG and JSON exports are made on your device, and before either is made we say plainly that other people’s names are in it. Records on your device remain until you delete them or clear browser data; synced records are deleted when you delete them or ask us to delete your account.

플레이스(장소 지도) / Place map

플레이스 기능을 쓰면 이용자가 직접 표시한 가 본 나라(국가 코드·첫 방문 연도·거주 여부·메모), 도시(이름·좌표), 핀(이름·분류·좌표·날짜·메모·사진·함께 간 사람·연결된 라이프 사건)이 기록됩니다. 기본 저장 위치는 이용자 브라우저의 로컬 저장소이며, Pro 클라우드 동기화를 켜면 사진을 제외한 기록이 함께 서버에 저장됩니다(일기 잠금을 켠 경우 암호화된 상태로).

위치는 자동으로 수집하지 않습니다. 자동 위치 추적, 방문 감지, 사진 EXIF 좌표 자동 수집 기능은 없습니다. 브라우저의 위치 권한은 핀 보기에서 이용자가 “내 위치” 버튼을 누를 때만 요청되며, 그때 좌표를 한 번 읽어 지도를 그 자리로 옮기고 점을 하나 찍습니다. 그 좌표는 저장되지도, 전송되지도 않습니다 — 핀으로 남기려면 지도를 눌러 직접 꽂아야 하고, 그렇게 꽂은 좌표만 기록됩니다. 권한을 거부해도 지도를 눌러 그대로 쓸 수 있습니다. 외부 지오코딩·장소 검색 API는 사용하지 않고, 나라와 도시 목록은 앱에 함께 담긴 Natural Earth(퍼블릭 도메인) 데이터에서 찾습니다. 핀 지도의 배경 타일은 OpenStreetMap에서 불러오므로, 그때 이용자의 IP와 보고 있는 지도 영역이 OpenStreetMap 서버에 전달됩니다(세계 보기는 타일을 쓰지 않아 아무것도 전달되지 않습니다). 집·직장 위치가 담길 수 있으므로 그림이나 백업을 공유하기 전에 확인하도록 안내합니다. 기기에 저장된 기록은 이용자가 지우거나 브라우저 데이터를 삭제할 때까지 남아 있으며, 서버에 동기화된 기록은 이용자가 지우거나 계정 삭제를 요청하면 삭제됩니다.

The Place map records the countries you colour in (code, first year, whether you lived there, a note), the cities you add (name and coordinates) and your pins (name, kind, coordinates, date, note, photo, who was there, and any life moment it belongs to). Saved in your browser by default; with Pro sync on it is stored on our server too — photos excepted — and encrypted when the diary lock is on. No location is ever collected automatically: there is no tracking, no visit detection and no reading coordinates out of photographs, The browser’s location permission is asked for only when you press the "where I am" button on the pin view; it then reads your position once, moves the map there and draws a dot. That position is neither saved nor sent anywhere — to keep a place you tap the map and drop a pin yourself, and only what you drop is recorded. Decline the permission and the map still works exactly the same way. No external geocoding or place-search service is used; countries and cities come from Natural Earth (public domain) data that ships with the app. The pin map loads its background tiles from OpenStreetMap, so your IP address and the area you are looking at reach their servers while you use it — the world view uses no tiles and sends nothing. Because your home and your workplace may be on it, we say so before an export is made. Records on your device remain until you delete them or clear browser data; synced records are deleted when you delete them or ask us to delete your account.

3. 광고·분석과 동의 / Advertising, analytics and consent

Google Analytics

24Houring 앱은 서비스 개선을 위해 Google Analytics 4로 방문·기능 사용 통계를 수집합니다. 유럽경제지역(EEA)·영국·스위스에서 접속한 경우에는 이용자가 ⚙ 메뉴의 “사용 통계 보내기”를 직접 켜기 전까지 Google Analytics를 불러오지 않습니다. 그 밖의 지역에서는 기본으로 켜져 있으며, 같은 메뉴에서 언제든 끌 수 있습니다. 접속 지역은 Cloudflare가 요청에 붙이는 국가 코드로만 판단하며 저장하지 않습니다.

Google Analytics는 통계를 위해 쿠키(_ga 등)를 사용합니다. 광고 저장소, 광고 개인화, Google 신호는 사용하지 않습니다. Google에 보내는 페이지 주소에서는 공유 코드와 로그인·결제 복귀 정보를 지우고 캠페인(utm) 값만 남기며, 시간표·일기·일정 내용은 보내지 않습니다. Google의 처리 방식은 Google 파트너 사이트의 데이터 사용 안내에서 볼 수 있고, Google 애널리틱스 차단 부가기능으로도 거부할 수 있습니다.

The 24Houring app uses Google Analytics 4 to measure visits and feature use. Visitors from the EEA, the UK and Switzerland do not load Google Analytics unless they turn on “Send usage statistics” in the ⚙ menu; elsewhere it is on by default and can be turned off in the same menu at any time. The region is judged only from the country code Cloudflare attaches to the request, which we do not store. Google Analytics uses cookies such as _ga. Advertising storage, ad personalization and Google signals are off. The page address sent to Google has share codes and sign-in/checkout return details removed, keeping only campaign (utm) values, and no schedule, diary or calendar content is sent. See how Google uses data from partner sites; you can also use the Google Analytics opt-out add-on.

광고 / Advertising

현재 24Houring은 Google AdSense 광고 스크립트를 불러오지 않으며, 안내 페이지(가이드·블로그 등)는 Google 스크립트를 불러오지 않습니다. 사이트 소유권 확인용 AdSense 메타태그와 ads.txt는 브라우저 저장소에 값을 쓰거나 광고 요청을 보내지 않습니다.

향후 광고를 활성화할 때는 적용 지역의 요건에 맞는 동의 절차를 먼저 마련하고 이 방침을 갱신합니다. 광고가 활성화되면 Google 등 제3자 공급업체가 쿠키를 사용해 이 사이트 또는 다른 사이트 방문 기록을 바탕으로 광고를 제공할 수 있습니다. 이용자는 Google 광고 설정에서 맞춤 광고를 관리할 수 있습니다. 자세한 내용은 Google의 광고 데이터 사용 안내를 참고하세요.

24Houring currently does not load Google AdSense advertising scripts, and the reading pages (guides, blog and similar) load no Google scripts. The AdSense ownership meta tag and ads.txt do not write browser storage or send an ad request. Before enabling advertising, we will implement the consent process required for applicable regions and update this policy. Once ads are enabled, third-party vendors including Google may use cookies to serve ads based on visits to this or other sites. You can manage personalized advertising in Google Ads Settings. See Google’s advertising data guidance.

Separately, the 24Houring server keeps daily counts of feature use, such as “opened the calendar” or “Pro offer shown”. A count holds only the event name and a one-word tag (for example, which screen showed the Pro offer). No account or device identifier, IP address, cookie, or schedule, diary or calendar content is stored. The counts are processed by 24Houring’s own server, not a third-party analytics tool, and cannot identify or follow any individual.

캘린더 이미지 저장·공유는 이용자의 기기 안에서 이미지를 만들며, 이미지를 서버로 보내지 않습니다.
